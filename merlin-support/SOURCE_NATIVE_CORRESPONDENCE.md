# Source and native namespace correspondence

`SourceNativeCorrespondenceOwner.bind(source_capability, count_capability)` accepts
only the original live reviewed source diagnostic and count correspondence
owners. The resulting separately reviewed mechanism is
`compiler_source_native_correspondence`, with the count owner's complete native
binding. `verify_compiler_binding(compiler_binding, *, native_binding)` checks
both actual five-field policy selections against their own original owners.

The source software digest remains the composite of exact selected input pins
and the original live staged-completion proof. The native software digest remains
the raw observed-contract digest. The adapter recomputes the composite and checks
all selected input pins against the original count correspondence; it never
substitutes one digest for the other. Numerical/runtime/library namespaces also
remain separate exact bindings, rather than being treated as interchangeable.

Issuance requires original owner types and callbacks. Revalidation reopens both
live capabilities, their original selected proofs, own/input source bytes, and
bound callback code. JSON reports cannot construct an owner. This establishes
structural namespace correspondence only: source numerical gates, emitted-program
checks, fresh complete outputs/counts, native domain/held gates, and all promotion
restrictions remain independently required. Default direct-binding semantics are
unchanged; the generic consumer must opt in explicitly to its separate bridge.

Tests use exact neutral stand-ins to exercise metadata/custody refusals; they
establish plumbing, not Gemmini or native timing qualification. No simulator,
compiler, fit or target workload is run by this adapter.

Metadata operations retain one original two-capability registry and use Merlin's
`scoped_registry_metadata_verification` for nested getters. Each operation checks
both original live owners at entry and exit. Callback/code/source, full binding,
identity and registry-roster checks still run, and explicit prototype, completion,
selected-source and count-correspondence checks remain fresh. Verification checks
the relation both before and after its binding comparison. Results are published
only after the transaction exits and this bridge's own custody is reopened.
No qualification result is cached between operations. The bridge and original
metadata implementation source bytes and callbacks are pinned. This changes host
metadata cost only; it does not change the frozen timing model or grant numerical,
completion, overlap, hardware, formal admission or promotion authority.
