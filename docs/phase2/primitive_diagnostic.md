# Explicit primitive L2 diagnostic

`gemmini_primitive_diagnostic.PrimitiveDiagnosticOwner` is an additional
operator-side checker for the original ordinary **layer** route. It does not
select a compiler, instantiate a capability from saved success, or call the
typed complete-model source attestation. Its constructor requires the actual
live `QualifiedZeroInitializerOwner`; both compared compilers must pass that
owner's original selected-release binding check.

The accepted source is one complete canonical public `merlin_iface` program:
resident pack, rank-two signed-i8 contraction, raw-i32 commit, and eviction.
It independently checks original declaration/command correspondence, complete
stimulus/reference arithmetic, selected mesh-panel and accumulator prefix
bounds, original current compiler snapshots, and retained executed-program-v2
roles. The original ordinary L0/L1/L2 must have executed and passed, including
complete output readback and required accelerator classes. Its result must
still report the original mandatory L3 as pending. A forged `pass` label,
copied tier, failed role or different source refuses.

For each exact current linked ELF, the checker runs the selected original
functional Spike with a bounded commit trace under its own shared CPU lease.
It proves the loaded original logical-pointer renderer belongs to the actual
completed build, then reopens linked input bytes and all observed CPU/device
writes. The existing independent packet-product checker reconstructs every
source product, accumulator continuation, zero initialization, raw readout and
complete output. The existing complete-tile permutation/RHS-omission checker
then checks only transformations justified by those actual effects.

```python
owner = PrimitiveDiagnosticOwner(original_live_qualification)
evidence = owner.check_pair(
    capsule_dir=original_current_capsule,
    baseline_result=baseline_run / "capsule_result.json",
    baseline_package=retained_baseline,
    candidate_result=candidate_run / "capsule_result.json",
    candidate_package=retained_candidate,
    work_root=new_original_operator_output,
)
```

The separately named v2 constructor
`PrimitiveDiagnosticOwner.from_rhs_qualification(original_live_rhs_owner)`
accepts only the exact original `QualifiedRhsResidencyOwner` and its checked
`RhsResidencyCompilerPrototype.seed: ZeroInitializerCompilerPrototype`.
It reopens the original RHS qualification before and after using that seed's
original bound base-release checker. It refuses an RHS-ledger compiler in
this seed-only route. This reuses no RHS/zero transformation admission: current
primitive arithmetic, inputs, actual packets, outputs and permitted issue
changes still receive the complete independent checks above. Neither JSON nor
arbitrary wrappers can select this context. The output records this distinct
compiler context; owner identity is versioned v2.

Arithmetic software, observed instruction effects and caller transport are
separate pinned roles. The caller checker requires the exact original
`BoundRoCCBackend`, selected facts, RTL source, runtime and pointer ABI. It
reopens the declared caller-source pins and rerenders with the original neutral
renderer, original pointer order and actual signed inputs. The completed
`harness.c` must match byte for byte; another renderer, input, pointer order,
transport or selected source refuses. This rederivation supplies no new
harness and does not equate an arithmetic-spec digest with a transport-contract
digest. Actual linked-byte/product/output checks still follow it.

Call after original ordinary grading releases its CPU lease. The checker owns
its leaf trace leases; a parent must not hold another lease while waiting.
Setup/byte-custody/verification wall costs remain separate from target cycles.
The output is `checked_actual_primitive_L2_pair`, never a full functional guard,
L3/certification verdict, hardware execution qualification or timing authority.
Fresh boxed timing observation and the frozen model's actual joint/count/host
domain checks remain separate. There is no performance incumbent promotion.

Original unsigned-range stimuli remain a cheap functional control. An additive
signed diagnostic uses the original `stimulus_range` API and independent
integer golden engine, with new declaration/reference identities and unchanged
raw signed-i8/i32 contract. It cannot inherit archived measurements merely
because its geometry or interface matches. The result reports whether each
actual operand is nonconstant and contains both signs.
