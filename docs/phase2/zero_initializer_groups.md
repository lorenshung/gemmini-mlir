# Candidate zero-initializer grouping

`merlin-support/backend/gemmini_zero_initializer_preparation.py` prepares a
separate copied compiler. It keeps the selected staged SDK, its source ledger,
and its numerical/effect declarations byte for byte. The enabled flag selects
ordinary candidate policy in `zero_initializer_policy.py`; the generic Merlin
source recognizer is copied exactly into candidate-owned `passes/`. This code
is not a new SDK export or a verifier grant.

For a sole-use private zero splat immediately before a signed rank-two
contraction, the candidate retains every original source operation in one task's
`source_op_indices`, omits only virtual initializer storage, and uses the
original target accumulator-zero, products and complete readout. Shared or
returned initializers remain materialized. Nonzero initializers retain the
original compiler refusal. Unknown semantic attributes do not authorize a
source group.

Focused tests check actual emitted C, command buffers, full source/task/ABI
accountability, preservation of returned outputs, unchanged selected sources and
refusals. A fresh native diagnostic on the sealed 17x16x32 signed source checked
all 544 output values with the original independent source/packet checker.
The disabled copied compiler reproduced the previous baseline command buffer and
LLVM byte for byte, so its original native/trace evidence was explicitly reused;
the enabled arm was freshly built, executed and traced. Its original complete
product/state/readout checks passed. Artifact:
`out/artifacts/target-adapters/gemmini/zero-initializer-native-v1/status.json`
in the managed Phase 2 pass-integration task.

This establishes a source-bound functional diagnostic, not a generally qualified
capability, hardware timing, or a latency improvement. The old staged pair
checker deliberately rejects its changed private ABI. A separate original
composite check is required before selecting this transformation through the
ordinary production capability route. The preserved Phase 1 package is unchanged.

The new `gemmini_zero_initializer_effects.ZeroInitializerRealizationChecker`
reopens each exact native/trace/source pair and runs the original complete
source/product/state/output proof. Its private Merlin inverse independently
rederives the closed source groups, checks the complete source/task/ABI change,
and rejects unrelated work, types, ordered outputs or storage changes. It never
imports the candidate's transformation code. Unknown outer linalg attributes
remain visible to this inverse.

Only after those checks may issued pointers be compared by their checked
logical ABI role. A renamed private accumulator-zero symbol is equivalent only
after the original linked ELF and all actual writes prove it zero and immutable.
All other command operands, configurations and fences must match. The explicit
composition option additionally uses the existing complete-tile permutation and
live immutable-RHS reload proof; it introduces no new allocation or overlap.
A fresh combined 17x16x32 candidate preserved all 544 complete outputs, removed
the host initializer and two actual RHS reloads, and passed this inverse. The
source-bound diagnostic is retained at
`out/artifacts/target-adapters/gemmini/zero-initializer-composite-v2/report.json`.

The realization checker is not a compiler capability issuer. Original clean
functional grade/certification, selected compiler/library binding, pre-freeze
composite preparation and ordinary capability transport remain separate gates.

The explicit original `gemmini_zero_initializer_registry.restore_registry`
factory performs cleanup admission followed by seven independently checked
initializer/composed-tile source pairs. Its live registry exposes
`zero_initializer_groups_raw_i32` separately from the current-artifact
`source_execution_diagnostic` issuer. Neither a saved success record nor an
import constructs either qualification. The original host must select the
exact factory inputs, SDK release and preparation policies before freezing
candidate source. Candidate policy and transformation sources remain editable;
the original complete source/native/effect/final-grade checks stay outside that
authority.

The opt-in sealed-parent protocol can inherit only the original live historical
qualification after kernel descriptor, callback, source, SDK and input custody
checks. It reopens every original compiler/native/trace pin and records inherited
qualification explicitly. Each newly emitted candidate still requires its own
native execution, bounded actual issue trace and independent complete source
proof. Missing original protocols, source pairs, exact ledger bindings or live
parent authority refuse selection. Shared source/grouped/attention contracts,
asynchronous overlap and unsupported readouts remain disabled. Current evidence
does not establish hardware certification, timing or a promoted incumbent.

Binding comparisons reopen all bounded ordinary ledger/component leaves between
fresh original-owner checks. Repeated getters within that comparison are not
additional independent evidence. The selected-library verifier still hashes
every current member; only immutable byte-identical syntax facts may be reused.
